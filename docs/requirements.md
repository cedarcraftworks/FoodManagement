# FoodManagement 要件定義書

最終更新：2026年11月3日

## 1. 目的

子ども食堂・フードバンクで、寄付された食品を**期限内に配り切り、期限切れによる廃棄を減らす**こと。

## 2. 想定している課題

以下は一般的に言われている課題をもとにした想定で、実際の団体への聞き取りで確かめる。

| 課題 | 今のやり方 | 起きること |
| --- | --- | --- |
| 期限の管理 | 紙・LINE・表計算 | 期限が近い物に気付くのが遅れ、廃棄が出る |
| 在庫の把握 | 倉庫や棚を見に行く | 配布の計画が立てにくい |
| 引き継ぎ | 口頭・メモ | 曜日ごとに入れ替わるボランティアの間で情報がずれる |
| 配る順番 | 経験のある人の勘 | 期限の早い物が後回しになる |
| 報告 | 手作業で集計 | 助成金・自治体への報告に時間がかかる |

## 3. 利用者

| 利用者 | できること |
| --- | --- |
| 管理者（団体を登録した人） | すべての操作、スタッフの追加、団体の設定の変更 |
| スタッフ（ボランティア） | 在庫の確認、入荷・廃棄・配布の記録、報告の確認 |

## 4. 機能要件

| ID | 機能 | 内容 |
| --- | --- | --- |
| F1 | ログインと役割 | 団体ごとに管理者とスタッフを分ける。他の団体のデータは見えない |
| F2 | 入荷の登録 | 商品名・種類・数量・期限（賞味／消費）・寄付元を登録 |
| F3 | バーコード | JANコードをカメラか手入力で読み、チェックデジットで確かめる。登録済みの商品は名前を自動で入れる |
| F4 | 期限順の在庫 | 期限が近い順に表示し、期限切れ・3日以内・7日以内を色で区別 |
| F5 | 配布の提案 | 世帯数と種類ごとの個数から、期限の早い在庫を割り当て、足りない種類を示す |
| F6 | 配布・廃棄の記録 | 提案を確定すると在庫が減る。廃棄も記録できる |
| F7 | 同時更新の検知 | 他のスタッフが先に更新していたら上書きせず、最新の在庫でやり直してもらう |
| F8 | 月次の報告 | 受入・配布・廃棄の個数と廃棄率を種類別に集計 |
| F9 | デモ | 架空の団体の在庫で、登録なしで試せる |

## 5. 非機能要件

| 項目 | 内容 |
| --- | --- |
| 使いやすさ | スマホの画面幅で片手で操作できる |
| 正確さ | 在庫数は入出庫の履歴と一致し、マイナスにならない |
| 食品の安全 | 消費期限切れは提案に含めない（設定でも変えられない） |
| セキュリティ | パスワードは BCrypt、ログインのトークンは SHA-256 のハッシュだけを保存。すべての SQL を団体で絞り込む |
| 品質 | 3言語の自動テストとブラウザでの E2E テストを、変更のたびに GitHub Actions で実行 |

## 6. 今回やらないこと

- 配布先の世帯の個人情報の管理（世帯数だけを扱う）
- 有料の商品データベースとの連携（団体の中で一度登録した商品を使い回す）
- 寄付者へのお礼状などの会計・寄付管理

## 7. 配布提案の規則（FEFO）

1. 種類ごとに「世帯数 × 1世帯あたりの個数」を必要数とする
2. 数量0の在庫と、消費期限切れの在庫は除く。賞味期限切れは団体の設定で「含める」ときだけ含める（初期値は含めない）
3. 期限の早い順、同じなら入荷の早い順に並べる
4. 必要数に達するまで割り当てる
5. 足りない分を「○○が △ 個足りません」として示す

各割り当てに「期限まで2日」などの理由を付ける。「今日」の日付は外から渡し、テストではどの日でも同じ結果になる。

期限の表示区分：期限切れ（今日より前）／3日以内（今日を含む）／7日以内／それ以降。

## 8. 同時更新への対策（楽観的ロック）

在庫ごとに版番号（version）を持たせ、次の1つの SQL で更新する。

```sql
UPDATE lots SET quantity = quantity - :n, version = version + 1
WHERE organization_id = :org AND id = :id AND version = :version AND quantity >= :n
```

- 更新できた行が0なら、他のスタッフが先に更新したか在庫が足りないので 409（Conflict）を返す
- 配布の確定は1つのトランザクションで、どれか1つでも失敗したら全部取り消す
- 在庫の数を変えるときは、同じトランザクションで入出庫の履歴を1行追加する

## 9. データ設計

| テーブル | 主な項目 | 役割 |
| --- | --- | --- |
| organizations | 団体名、賞味期限切れを配布に含めるか | 団体 |
| users | 団体、メール、パスワードのハッシュ、役割 | スタッフ |
| sessions | トークンのハッシュ、有効期限 | ログイン中のトークン |
| items | 団体、JANコード、商品名、種類 | 商品 |
| lots | 商品、数量（0以上）、期限、期限の種類、入荷日、寄付元、version | 在庫（期限ごとのまとまり） |
| movements | 在庫、種類（受入／配布／廃棄）、数量、操作したスタッフ、日付 | 入出庫の履歴 |

詳しくは [api/src/main/resources/db/migration/V1__init.sql](../api/src/main/resources/db/migration/V1__init.sql)。

## 10. API

| メソッド | パス | 内容 | 権限 |
| --- | --- | --- | --- |
| POST | /api/auth/register | 団体を登録（登録した人が管理者） | なし |
| POST | /api/auth/login, /api/auth/logout | ログイン・ログアウト | なし／ログイン |
| GET | /api/me | ログイン中のスタッフと団体 | ログイン |
| PUT | /api/organization/settings | 賞味期限切れを含めるか | 管理者 |
| POST | /api/staff | スタッフの追加 | 管理者 |
| GET | /api/lots | 在庫（期限の早い順） | ログイン |
| POST | /api/lots | 入荷 | ログイン |
| POST | /api/lots/{id}/dispose | 廃棄（version が必要） | ログイン |
| GET | /api/items/by-jan/{jan} | バーコードから商品を探す | ログイン |
| POST | /api/distributions/plan | 配布の提案 | ログイン |
| POST | /api/distributions | 配布の確定（version が必要） | ログイン |
| GET | /api/reports/monthly?month=2026-10 | 月次の報告 | ログイン |

起動後、`/swagger-ui.html` で仕様書を見て試せる。
